# UI改善ループ: キャラクターを主役にしたレイアウト — 2026-06-19

## 背景 / なぜ

ユーザーから `/goal`: 「キャラクターが会話履歴に押しつぶされて小さい。UIがシンプルすぎて
ミニマルな印象が逆効果。人間性・身近さを感じさせる画面にするため、インターネット調査も
含めて自律的にUI/UXを改善するループを回してほしい」との指示。

## 調査

WebSearchで「AI companion app UI design」系の記事(Replika/Character.AI/Talkie AI等の
UXレビュー)を調査。共通する設計原則:
- アバターを画面の主役にし、チャットは画面を支配しない(全画面チャットログ+小さいアバター、
  ではなく逆)
- 背景は柔らかい光・グラデーションで「夢見るような」温度感を出す(フラットな白背景は不可)
- キャラクターの顔が大きく見えることが感情的なつながりに直結する

## 変更前の問題点(v1)

- `RootView` が `VStack` でヘッダー→固定220ptのアバター→残り全部をチャットログという構成。
  チャット履歴が伸びるほどアバターは相対的に小さく見え、実際には固定サイズでも画面上の
  「主役感」が無かった。
- 背景は既定の白(システム背景色)で、雰囲気・奥行きが無くミニマルすぎた。

## 変更内容

1. **`AmbientBackground.swift`(新規)**: 感情ごとに色が変わるグラデーション背景
   (`LinearGradient`+ゆっくり動く`RadialGradient`)。フラットな白を排除し、空間に
   温度感と奥行きを出す。
2. **`RootView.swift`(再構成)**: `VStack`構成をやめ`ZStack`に変更。
   - 背景: `AmbientBackground`
   - 中間層: アバター(`VRMAvatarView`)を `.ignoresSafeArea` で画面全体に配置
     (固定220pt枠を撤廃し、キャラクターが本当に「画面いっぱい」になるようにした)
   - 前面層: ヘッダー(上部、黒グラデーションのスクリムで視認性確保)+
     `ConversationOverlay`(下部のみ)
   - `.preferredColorScheme(.dark)` でステータスバー等を背景に合わせる
3. **`ConversationOverlay.swift`(新規、`ChatView.swift`を置き換え)**:
   - 既定では**直近2件のメッセージだけ**を半透明カード(`.ultraThinMaterial`)でアバターの
     上に重ねる。フルスクリーンの会話ログでアバターを押しつぶさない。
   - カードをタップすると、従来の全履歴チャットログが**ボトムシート**(`.sheet`、
     `.medium`/`.large` detents)として展開する。履歴を消したわけではなく、既定表示から
     退避しただけ。
   - 入力欄はオーバーレイの下部に常時表示(`.ultraThinMaterial`の角丸カプセル)。
4. **`viewer.ts` に framing オーバーライドを追加**: `CompanionViewer` のコンストラクタが
   `cameraPosition`/`cameraLookAt` を任意で受け取れるようにした(未指定ならWeb版の既存値の
   ままで**Web版の見た目に影響なし**)。`frontend/src/ios-avatar/entry.ts` だけがこれを使い、
   縦長フルブリード表示に合わせて少し寄った(顔・上半身が大きく見える)framing を指定。

## 検証

- `npx tsc --noEmit`(frontend)→ exit 0。`xcodegen generate` → `xcodebuild`(MCP経由)→
  ビルド成功(警告0)。
- フロントエンドを再ビルドし、`backend/static/ios-avatar/` に新framingを含む
  `avatar.bundle.js` を反映 → 本番Workerへデプロイ(`realistic.vrm`は通常運用通り一時退避)。
- シミュレータで実機相当の動作確認: 変更前後のスクリーンショットを比較し、
  - キャラクターが画面全体を占める配置になったこと
  - 感情に応じた背景色のグラデーションが効いていること
  - チャットが「最新2件+展開ボタン」の半透明オーバーレイになり、アバターを隠さないこと
  を確認。
