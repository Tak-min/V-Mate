# プロダクト優先度・デザイン・収益化方針（2026-07-21）

## 結論

v-mate は「恋愛の代替」ではなく、**毎日に参加する推しの相棒**として設計する。無料の核は
`会話 → 記憶される → 日記・自発的な声かけで後から返ってくる` 体験であり、親密度や人格は
課金で止めない。収益化は、成人ユーザーに対する **継続体験の拡張（サブスク）** を最初に検証し、
次に **自己表現の拡張（ボイスパック）** を導入する。

最初の収益化実装は決済ではない。匿名 Cookie のままでは再インストール・機種変更時に購入復元
できないため、Sign in with Apple、匿名データ移行、アカウント削除が先行条件になる。

## 根拠と確度

### 確認済み

- Web/iOS ともに音声会話、永続記憶、日記、自発的な声かけ、3D 表情という差別化資産がある。
  `README.md`、現行ソースを確認。
- 親密度は `kv.affinity` で無料のまま「相棒」まで上がる。画面上ではハート記号を使い、
  現行色はピンク／ラベンダー寄りである。
- iOS は匿名 Cookie のみで、Sign in with Apple、Keychain による JWT 保持、購入復元は未実装。
- 年齢ゲート、未成年向けモデレーション、通報導線は `0e4c1ba` で実装済み。古い
  `monetization_auth_and_safety_2026-07-20.md` の「未実装」記述は失効している。
- TTS は Worker 側の `AIVIS_MODEL_UUID` で決まる。ボイスパックはクライアント資産配信なしで
  実現できる余地が大きい。
- 3D ビューアはモデル URL を受け取れるが、衣装ごとの物理・コライダー・表情互換は未検証である。

### 未検証（先に計測する）

- 初回会話完了率、翌日／7日継続率、音声利用率、日記閲覧率、支払意思、TTS 原価。
- ボイスと衣装のどちらに支払うか、適正価格、スポンサー表示への受容性。

## デザイン方針

### 体験の中心

初回セッション内で、説明ではなく次の因果を体験させる。

1. ユーザーがシロに一つ話す。
2. シロがその内容を覚えたことを短く、過剰に擬人化せず示す。
3. セッション後に日記または次回の声かけで、その記憶が自然に返ってくる。

この「時間をまたぐ応答」を北極星体験とする。3D・音声・日記はそれを強める手段であり、機能数を
見せるオンボーディングにはしない。

### 表現ルール

- 「恋人」「独占」「関係性を買う」表現は使わない。安全方針と対等な相棒という価値を守る。
- 親密度は課金状態ではなく、会話の積み重ねと口調・日記文脈を説明する無料の進捗表現に留める。
- ハートとピンクの過剰な恋愛記号は、互換性を保ちながら暖かい琥珀と深い青緑、
  「応援」「記録」「一緒に育つ」を示す記号へ段階的に移す。既存ユーザーの体験を一括で反転させない。
- 有料のボイス／衣装は、シロとの基本的な関係を売るものではなく、推し方を自分らしく表現する
  カスタマイズとして説明する。

## 収益化の順序

| 段階 | 提供価値 | 判断 | 理由 |
| --- | --- | --- | --- |
| 1 | サブスク | 最初に検証 | 会話・TTS 利用枠、日記の履歴／頻度など、継続利用と原価に直結する価値を提供できる。 |
| 2 | ボイスパック | サブスク後 | Aivis モデル UUID のサーバ側選択で開始でき、衣装より実装・品質保証が軽い。 |
| 3 | 衣装 | ボイスの学習後 | VRM 資産、貫通防止、表情／リップシンクの視覚 QA が商品価値の中心で、先行投資が大きい。 |
| 4 | 投げ銭 | 初期リリースから除外 | 消費型 IAP、返金、審査、価値説明の負荷に対し、初期の学習価値が低い。 |
| 5 | スポンサー | 凍結 | 明示ラベル、編集方針、ブランド適合性が必要。継続利用の基盤ができてから判断する。 |

価格は現時点で固定しない。TestFlight／早期利用者で「何に払うか」を観察し、定性インタビューと
行動データが一致してから価格実験へ進む。

## 開発優先度

| 優先 | 成果 | 完了条件 |
| --- | --- | --- |
| P0 | 現在の公開前安全性と作業中 UI を守る | 年齢ゲート・モデレーションを回帰させず、未コミットの iOS UI 差分を変更しない。 |
| P1 | 安定したアカウント | Sign in with Apple、Keychain JWT、匿名履歴の一回限り移行、再ログイン、アカウント削除。 |
| P2 | リリース可能な中核体験と計測 | 北極星体験を反映するオンボーディング、匿名化イベント、TTS 使用量・失敗・クラッシュの可視化。 |
| P3 | 権利基盤 | entitlements、購入台帳、カタログ、成人サーバ側ゲート、冪等 API。 |
| P4 | StoreKit 2 サブスク | 購入、復元、失効／返金通知、購入管理画面。 |
| P5 | ボイスパック | 所有権確認、選択、Aivis モデル切替、プラン別クォータ。 |
| P6 | 衣装 | 共通ビューアの差替え、各 VRM の互換・実機視覚 QA。 |
| P7 | 投げ銭・スポンサー | P1–P6 の利用・収益データを基に個別に再判断。 |

P1 を P3 より先に置く。購入は復元できて初めてユーザーの権利になるためである。P2 は P1 と並行して
よいが、既存 UI の未コミット変更とは別の変更単位にする。

## 実装設計

### P1: 認証、移行、削除

- `identities(provider, external_id, user_id, email)` を追加し、Apple の `sub` を唯一キーにする。
  `users.email` と `password_hash` は NULL 許容へ一回だけ移行する。合成メールやダミーパスワードは使わない。
- Worker は Apple identity token の `iss`、`aud`、`exp`、nonce、RS256/JWKS 署名を検証する。
- iOS は `AuthenticationServices`、nonce の SHA-256、Keychain を使う。`APIClient` は JWT がある場合のみ
  Bearer ヘッダを付与する。
- 新規 Apple ID への初回連携時だけ、匿名 ID の `messages`、`facts`、`diary`、`kv`、`user_age` を移す。
  既存 identity への再ログインで再移行・上書きしない。
- `POST /api/auth/delete` はアプリの Keychain とサーバ上のユーザーデータを削除する。サブスク解約は
  App Store の管理画面で別途必要なことを UI に明示する。

### P3–P5: 権利と決済

- `entitlements` を有効権利の正本、`purchases` を外部取引 ID が UNIQUE の追記型台帳にする。
- `GET /api/entitlements` と、所有権を確認して選択状態を更新する API を用意する。クライアントの
  購入状態は信頼しない。
- iOS は StoreKit 2 と App Store Server Notifications V2 を使う。取引 JWS の検証、通知再配信、
  返金・失効処理を冪等にする。iOS アプリ内に Stripe 導線は置かない。
- 最初の有料特典は、人格・感情・親密度ではなく、会話／TTS の利用枠と日記の継続価値に限定する。
  サーバ側クォータを唯一の制御点にする。

### P5–P6: 表現の拡張

- ボイスパックは、選択済みパックの `aivis_model_uuid` をサーバ側で解決して TTS に渡す。
- 衣装は、権利確認後に解決した `vrm_url` を共通ビューアへ渡す。各モデルについてロード失敗、
  リップシンク、表情、髪・衣服の貫通を Web と iOS 実機で確認する。

## 計測とゲート

サブスクを公開する前に、少なくとも次のイベントを匿名化して計測する。

- onboarding 完了、初回会話完了、初回記憶確認、初回日記閲覧
- D1/D7 継続、会話ターン数、音声会話時間、TTS 成功／失敗・利用量
- 課金画面閲覧、購入開始、購入成功、復元成功、解約導線閲覧

意思決定は次の順で行う。初回の北極星体験に到達しない場合は、課金開発よりオンボーディングを直す。
到達するが継続しない場合は、日記・記憶・自発的な声かけを改善する。継続するが購入されない場合だけ、
サブスクの価値・価格・ボイスパック仮説を検証する。

## 必須の検証

- 認証: `iss`／`aud`／期限／署名／nonce の拒否テスト、新規・再ログイン・匿名移行を実機で確認。
- 移行: 全ユーザー表が移り、既存アカウントが再移行で上書きされないこと。
- 課金: 同一 transaction ID の並行要求、通知再配信、返金／失効で二重付与しないこと。
- 年齢: unknown／minor／under13 の購入 API が必ず 403、iOS UI にも購入導線を出さないこと。
- 原価: プラン・日別の TTS クォータと 429 時の穏やかな案内を検証する。
- 視覚: 衣装ごとの VRM 実機 QA を完了条件にする。
