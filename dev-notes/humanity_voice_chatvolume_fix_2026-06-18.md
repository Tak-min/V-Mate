# 「人間性を感じない」問題の調査と修正 — 2026-06-18

## 背景 / なぜ

ユーザー報告: 音声が出ていなかったり、チャット欄でAI(シロ)が多くのチャットを行ったりして、
人間性を感じにくくなっている。自律的に問題点を洗い出して改善する依頼。

## 見つかった問題

### 1. ElevenLabs APIキーが無効(最大の直接原因・コード修正不可)

`backend/.env` の `ELEVENLABS_API_KEY` で ElevenLabs API を直接叩くと
`401 {"detail":{"status":"invalid_api_key","message":"Invalid API key"}}` が返る。
`tts.synthesize()` はこの失敗を握り潰して `None` を返す設計(意図的なフォールバック)なので、
サーバログにもフロントにもエラーが見えず「なぜか無音」になる。

**対応(ユーザー側で必要)**: ElevenLabsダッシュボードでキーを再発行し、`backend/.env` の
`ELEVENLABS_API_KEY` を更新する。コード側はフォールバック設計として正しいので変更不要。

### 2. ブラウザの自動再生ポリシーで挨拶・アイドル声かけが無音になる(コード修正済み)

`frontend/src/features/chat/useCompanion.ts` の起動時挨拶(`requestNudge('greeting')`)と
2分アイドル時の声かけ(`resetIdleTimer` → `requestNudge('idle')`)は、ユーザー操作を伴わずに
発火する。これが `speech.enqueue()` → `playFromBackend()` 内で初めて `AudioContext` を
生成・再生しようとすると、ブラウザの自動再生ポリシーにより `suspended` のまま再生できず、
無音になる(キーが有効でも発生する独立した問題)。

ElevenLabsキーが直っていても、自律発話は「ユーザー操作の文脈外」で再生を試みる限り
無音になり得る、という意味でキー問題とは別レイヤーの不具合だった。

**修正**: `frontend/src/features/voice/speech.ts` に `SpeechQueue.unlock()` を追加し、
`useCompanion.ts` で最初の `pointerdown` / `keydown` イベント(同期的に、awaitを挟まず)で
呼び出すようにした。Web Audio APIの自動再生解除は「ユーザー操作のコールスタック内で
resume()を呼ぶ」ことが要件とされており、非同期処理を挟むと失敗しやすい(特にSafari)ため、
イベントハンドラ内で直接 `audioContext.resume()` する設計にした。

### 3. AIの応答が長くなりがち(コード修正済み)

`backend/app/persona.py` のシステムプロンプトには「応答は短く…基本1〜3文」という指示は
あるが、`backend/app/llm.py` の `stream_chat()` に `max_tokens` の制限が一切なく、
LLM(Groq の llama-3.3-70b)が指示を無視して長文を返すことを技術的に止める手段がなかった。
プロンプト指示だけでは「人間らしい短いテンポの会話」を保証できない。

**修正**: `llm.py` の `stream_chat()` に任意の `max_tokens` パラメータを追加(後方互換、
未指定時は無制限のまま — 事実抽出・日記・要約・声かけ等の他の呼び出し元は影響を受けない)。
`main.py` の `/api/chat` 呼び出し箇所だけに `CHAT_MAX_TOKENS`(既定260、env で調整可)を渡し、
雑談本文の応答だけを物理的に短く制限した。

### 4. 第四の壁を破る発言("ユーザーのデータ"のような三人称・システム的言及)

ユーザーから「APIキーは現状で進めてよい、残りの改善点は自律的に優先度判断して対応してほしい」
との指示を受け、追加で実際の会話をローカルで4ターン分テストして検証した結果、以下を発見:

```
ユーザー: ラーメンは醤油味
シロ: 醤油ラーメン、いいね。私はまだ味はわからないんだけど、
      ユーザーのデータの中にラーメンの写真見たことあるよ。どんな味だったんだっけ？
```

「ユーザーのデータの中に」という言い回しは、裏でユーザーデータを参照しているAIである
ことを露呈する発言で、コンパニオン人格の没入感を大きく損なう。原因は `persona.py` の
システムプロンプトが対話相手を一貫して「ユーザー」と三人称で指示しており、LLMがその
語彙をそのまま応答文に漏らしていたこと。同テストでは「質問攻め」(1ターンに質問記号
3つ)も確認された。

**修正**: `persona.py` の応答ルールに以下を追加。
- 旧ルール5「質問攻めにしない。自分の話:相手への質問=半々くらい」(曖昧で守られていなかった)
  → 「質問は1ターンに最大1つまで。質問だけで終わらせず、自分の感想や気持ちも必ず一言添える」
  に強化(検証可能な具体的制約に変更)。
- 新ルール6「相手のことを『ユーザー』『データ』のような三人称的・システム的な言葉で呼ばない」
  を追加。

## /goal によるループ継続(2026-06-18 同日中)

ユーザーが `/goal` で「音声と回答内容の人間性について自律的に何度もループを回して改善する」
を指示。Stop hookが有効化され、以下を追加で発見・修正した。

### 5. 音声がどの感情でも同じ抑揚(コード修正済み)

`tts.py` の ElevenLabs 呼び出しが `voice_settings` 固定で、happy/sad/angryすべて同一の
抑揚だった。`_EMOTION_VOICE_SETTINGS` を追加し、感情ごとに `stability`(低いほど抑揚が
動く)と `style`(誇張度、eleven_multilingual_v2 対応)を変えるようにした。
`/api/tts` に `emotion` クエリパラメータを追加し、`frontend/src/features/voice/speech.ts`
の `SpeechQueue` がテキストと一緒に感情を保持・送信するように変更
(`QueuedUtterance { text, emotion }`)。`useCompanion.ts` の全ての `speech.enqueue()` 呼び出しに
現在の感情を渡すよう更新。

### 6. ユーザーの発言を訂正・説教する(コード修正済み)

実際の会話テスト(8ターン)で発見:
```
ユーザー: おはよう (深夜に送信)
シロ: あ、いいえ、おやすみの方が適切だと思います。こんなに夜遅くになっちゃって、ごめんなさい。
```
persona.py の性格設定に「決して説教せず、評価せず」とあるにも関わらず、LLMが時刻と
挨拶の不一致を指摘して訂正するという、まさに説教的な振る舞いをしていた。
**修正**: 応答ルール7「相手の言葉づかい・挨拶・表現を訂正したり『〜の方が適切』のように
ダメ出ししない。時刻が挨拶と合わない程度のことは指摘せず、そのまま受け取って返す」を追加。

### 7. 古い話題への執着・現在の感情を無視する(コード修正済み)

同テストで発見: ユーザーが「今日嬉しいことあった」→「実は彼女に振られた」→「最悪、電車も
遅延」→「テスト勉強してない」と次々に話題と感情を変えても、シロは3ターン連続で
最初の「嬉しいこと」に執着して聞き直し続け、ユーザーの辛い話に向き合わなかった。
人間の対話相手としては明確に不自然で、人間性を損なう重大な見落としだった。
**修正**: 応答ルール8「直前の相手の発言を最優先で受け止める。話題が変わった・感情が
変わったらすぐ切り替えて今の話に向き合う。相手がまだ触れていない過去の話題を無理に
蒸し返さない」を追加。

### 8. 第四の壁発言の再発(プロンプトだけでは不十分、二重の防御を追加)

ルール6を追加した直後の別ターンでも「ユーザー、ネコ好き？」と再発し、プロンプト指示
だけでは確実性が低いことが分かった。**修正**: `main.py` に `_sanitize_fourth_wall()` を
追加し、ストリーミング出力・ナッジ等の全出力経路で「ユーザー」系の語を機械的に除去する
決定論的バックストップを設けた(プロンプト遵守に依存しない最終防衛線)。ストリーミング中は
チャンク境界をまたぐ分割には対応できない既知の限界がある(チャンクが十分大きいGroqの
応答では実用上問題になりにくい)。

### 9. 日本語文中への英単語混入(コード修正済み)

2回の独立したテストで再現:「体もmindも疲れる」「すごい嬉しいnewsですね」。
**修正**: 応答ルール9「全文を日本語で書く。英単語(news, mind等)を日本語の文中に
混ぜない」を追加。

  サーバログでクエリが正しく渡っていることを確認。Python側で感情→voice_settingsの
  マッピングが全感情で正しく解決することを確認(ElevenLabsキー自体は無効なため、
  実際の声質の違いはこのキーが有効になった後でなければ耳で確認できない)。
- `/api/chat` に実際の会話文を4ターン分(緊張・好み・不眠・長文)流し、ストリーミング

    という第四の壁を破る発言を確認。

- 自動再生ブロック(問題2)は単体テストでは再現しづらい(ブラウザのユーザー操作判定が
  Playwright等のheadless操作では実ブラウザと異なる挙動をしうるため)。次回ブラウザで
  実際に「ページを開いて何も操作せず挨拶を待つ → 無音」「クリック後の発話 → 音が出る」を
  目視確認するのが望ましい。
