## 1. 調査した「工夫」と批判的評価(エビデンスの強さで層別)

### エビデンスが比較的強い(実装する価値が高い)
- **音声の不完全性(フィラー/ブレス/抑揚)**: Google Duplex のフィラー予測、Amazon Polly の SSML breath
  (MOS 3.20→3.87)、vishing 研究で「人間と誤認される率が高い」。60〜90秒超の発話で息継ぎが無いと急に
  合成音声感。**VRM+音声型の v-mate に最も相性が良い最重要レバー**。
- **バックチャネリング(相づち)**: 言語学(Yngve 1970)+ EMNLP 2024 実証で engagement 向上。ただし
  音声のターンテイキング前提で、テキストへの単純転用はタイミングを誤ると逆効果。v-mate は frontend
  `waitingCueFor` で送信直後の繋ぎ相づちを既に実装済。

### 文脈依存・cargo-cult 寄り(安易に入れると逆効果)
- **可変タイピング遅延 + インジケータ**: 実装が簡単で流行しているが、効果量は小さく文脈依存。
  **経験豊富なユーザーには「白々しい演技」と見抜かれ逆効果**(Opposing Effects of Response Time, BISE 2022)、
  **速さが期待される文脈では遅延そのものが不満要因**。2025年の研究では有意差なしの報告も。
  → **v-mate には足さない判断**: 既にLLM由来の自然な遅延 + 相づち cue + 3点ドットがあり、有機的な「間」が
  既に存在する。人為的遅延の上乗せはまさにこの罠。
- **絵文字**: hedonic(雑談)文脈では親近感を上げるが informational では「非専門的」と逆評価。bot が使うと
  人間が使うときより効果が減衰。万能ではない。
- **テキストのフィラー/わざとのタイポ**: 直接の実証研究が乏しく、信頼性毀損リスクの方が大きい。→ 不採用。

### 商用バイアス疑い・効果量が不明
- **記憶のコールバック(過去発言の蒸し返し)/ 時間経過の認識**: 直感的説得力と関係性心理学の「応答性」
  理論はあるが、効果量を測った独立学術研究が薄く「2倍の再訪率」等は商用ブログ出典。v-mate は facts/
  summary/diary/「N日ぶり」を既に実装済(理論的に妥当な範囲で導入済み)。
- **プロアクティブ・メッセージの最適頻度**: Meta の実務制限(14日/5メッセージ/拒否後24時間抑制)は参考に
  なるが、学術サーベイは「無視率が高い」と否定的データ。

### 倫理的に最も警戒すべき(エンゲージとwell-beingが逆相関)
- **感情ミラーリング / 自己開示の誘導**: 相互開示でラポールは上がるが、**コンパニオン用途では自己開示が
  多いほど well-being が下がる**逆転現象が実証(ScienceDirect 2025)。Replika は FTC 告発で
  **love-bombing**(早期に親密メッセージで依存させる)と批判。「自己開示の非対称性」(AIは開示し返せない)
  という構造的欠陥+幻滅(false connection)リスク。
- **メタ教訓(不気味の谷)**: 人間らしさを上げ続けると、ある点から急に不快感へ転化(Sesame AI)。
  **「人間らしさ最大化」を目標関数にすること自体が罠**。意図的に人工性の痕跡を残すべき。

## 2. v-mate への適用判断(批判的に「やらないこと」を先に確定)
- ❌ **人為的タイピング遅延を足さない**(上記の通り既存の有機的遅延で十分、上乗せは逆効果)。
- ❌ **プロアクティブ頻度を上げない**(既に `IDLE_NUDGE_MS=240s`/`GREETING_MIN_GAP=180s` に過干渉対策で
  抑制済。研究=FTC/well-being はこの保守性を**支持**)。
- ❌ **テキストのフィラー/タイポを足さない**。
- ✅ **well-being の歯止めをプロンプトに明文化**(依存誘発・過剰深刻演出の禁止)。

## 3. 実装したこと(IT-A+B・本番デプロイ/検証済み)
commit `af45905` / 本番 Version `f648b846` / `worker/src/persona.ts buildSystemPrompt` に
「## 寄り添い方」セクションを **additive** に追加(既存ルール1-9・短文/感情タグ/「ユーザー」呼び禁止は温存):
- **A トーン反応性**: 「何を」でなく「どう言ったか」(感情の温度)を先に読んで受け止める
  (弾んでいれば一緒に弾み、沈んでいればトーンを落として寄り添う)。= 調査で「不気味の谷の核・誰も十分
  できていない差別化点」とされた "反応的情動性" を text 側で具体化。
- **B 節度ある脆弱性**: 素の気持ち・小さな弱さ・いま感じたことを時おり見せてよい/完璧に応えようとしすぎず
  気取らない素直さを残す(不気味の谷回避)。= 相互開示の人間性。
- **well-being 歯止め**: 依存させようとしない/過剰に深刻な感情を演出しない/対等で軽やかに。

## 4. 落とし穴(Symptom → Cause → Fix)
- **Symptom**: 本番 `/api/chat` を Python `urllib` で叩くと **HTTP 403 Forbidden**(`/api/nudge` を curl で
  叩いた時は 200 だった)。
  **Cause**: worker に Origin/CSRF チェックは無い(grep 確認済)。**Cloudflare エッジが `Python-urllib/x` の
  User-Agent をボットとしてブロック**していた。
  **Fix**: urllib リクエストに**ブラウザ風 `User-Agent`** を付ける(`Mozilla/5.0 ... Chrome/...`)と 200。
  curl は既定UAで通る。**本番API検証スクリプトには必ずブラウザUAを付ける**(再利用ノウハウ)。
- プロンプト文字列のみの additive 変更は **コードロジック非該当 → 独立コードレビューより本番curlでの
  行動検証(複数トーン+既存挙動の回帰)の方が有効なゲート**、という判断で review-agent を省略した。

## 5. 申し送り(未実装=意図的)
- **Track C(音声の呼吸・間 + 感情連動プロソディ)**: 研究上の**最重要レバー**(VRM+音声の強み)。だが
  **音質の人間性向上はヘッドレスで検証不能=ユーザーの耳が必須**(本リポジトリの voice 変更が一貫して
  抱える制約)。ブラインドで本番投入すると過剰な間/不自然さを作っても気づけないため見送り。実装仕様:
  - `worker/src/tts.ts`: 現状 `speaking_rate`/`emotional_intensity`/`volume`/`leading_silence_seconds=0`。
    Aivis Cloud API が **SSML / break / breath / pause 系パラメータ**を持つか要確認(context7 or 公式docs)。
    あれば感情別に微小な間・抑揚の揺れを付与(sad=遅め+間を長く 等)。**不気味の谷回避のため流暢さの追求は
    しない**。`leading_silence_seconds=0` は没入レイテンシ最適化なので触る場合はトレードオフを実機で要確認。
  - 代替(Aivisがpause非対応の場合): frontend `speech.ts SentenceSplitter`/`SpeechQueue` で感情に応じた
    文間の微小ポーズを挿入(ただし過去に無音ギャップ排除の修正をした経緯があり、相反するので慎重に)。
  - **検証はユーザーに「より人間らしく聞こえるか/不自然な間が出ていないか」を実機で聞いてもらう前提**で着手。
- **共有体験のエピソード記憶**(Nomi「昨日一緒にハイキングした」型): 効果は大きいが実装コスト高+
  ヘッドレス検証性低。diary が部分的に担う。将来検討。
