# 会話中に視線が固定されて見える問題の修正 — 2026-06-18

## 背景 / なぜ

[[abaabe4]] (視線のランダム性を強化) でワイドグランス(部屋のあちこちを見る大きめの視線そらし)を
追加したが、その後の確認で「会話中(listening/speaking/typing)だけ一点を凝視しているように
見える」副作用が残っていた。原因は2つ重なっていた:

1. `wideGlanceChance` が `listening: 0.16 / speaking: 0.12 / typing: 0.08` と、idle(0.26)に比べて
   会話中だけ極端に低く設定されていた。
2. `directness` の上限が `0.94` まで上がり得る設計で、`(1 - directness)` を視線オフセットの
   スケールに使っていたため、directness が高いときに `gazeOffset` がほぼゼロまで潰れて
   「完全固定」に近づいていた。

## 変更内容 (`frontend/src/features/vrm/viewer.ts`)

- `wideGlanceChance` を会話中モードでも全体的に上げた: `listening 0.22 / speaking 0.2 / typing 0.16`
  (idle 0.26 はそのまま)。
- `directness` の上限を `0.94` → `0.78` に下げ、`relationshipWarmth` による加算も `0.16` → `0.1` に縮小。
- 新たに `gazeVisibility = Math.max(1 - directness, 0.4)` を導入し、directness がどれだけ高くても
  視線オフセットの可視性が `0.4` 未満には潰れないよう下限を設けた。`(1 - directness)` を直接使う
  箇所をこの `gazeVisibility` に置き換え。
- `randomBlinkInterval` の `attentionScale` に `listening: 0.85` を追加(以前は listening が
  分岐に含まれておらず idle 相当の `1` 扱いだった→会話中のまばたき間隔が間延びしていた)。
- `startBlink` のダブルブリンク確率を全体的に上げた(`shy 0.24→0.3`, `happy 0.12→0.18`,
  その他 `0.07→0.11`)。

## ハマりどころ

- 視線の不自然さは静止画スクリーンショットでは判定できない(アニメーションの時間変化が本質)。
  Playwright の `browser_take_screenshot` はこのプロジェクトではフォント読み込み待ちで
  一貫してタイムアウトし(WebGL/Canvas描画とフォント待機ロジックの相性問題と思われる、
  アプリ自体の不具合ではない)、画像での目視確認は今回できなかった。
- 代わりに実際のチャットフロー(Groq API経由で2往復送信)をPlaywrightで実行し、
  コンソールエラー0件・親密度ゲージ正常加算・キャラクター表示継続(クラッシュなし)を確認。
  視線/まばたきのアニメーション自体は、ロジック上の整合性(上記の数値変更)とコード内コメントの
  説明で妥当性を確認した、という位置づけ。実際の見た目の自然さは人間の目での最終確認が望ましい。
