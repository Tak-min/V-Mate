# AIの干渉(自発的なメッセージ・頻度)を減らす — 2026-06-19

## 背景 / なぜ

ユーザーから「AI側がユーザーに干渉しすぎている。メッセージ・アクション・インタラクションの
時間・回数・頻度を減らしてほしい。ただし飽きて使わなくなる程度には減らさない」との指示。

## 見つかった問題と修正

### 1. ページを開く(リロードする)たびに毎回挨拶し直す

`/api/nudge`(reason=greeting)に「直前にも会っていたかどうか」のチェックが無く、
`last_seen` が1分前でも1日前でも同じように毎回フルの挨拶メッセージ+音声を生成していた。
開発中の動作確認や、ユーザーが単にページをリロードした場合でも毎回律儀に挨拶し直すのは、
明確に「干渉しすぎ」に該当する。

**修正**: `last_seen` からの経過秒数が `GREETING_MIN_GAP_SECONDS`(既定180秒)未満なら、
「戻ってきた」とはみなさず挨拶を省略する(`{"text": "", "emotion": "neutral"}` を返す)。
`backend/app/main.py` の `/api/nudge` と、本番の `worker/src/index.ts` の `postNudge` の
両方に同じロジックを実装(`worker/src/util.ts` に `secondsSince` ヘルパーを新規追加)。

### 2. アイドル時の自発声かけが2分間隔と短すぎる

`frontend/src/features/chat/useCompanion.ts` の `IDLE_NUDGE_MS = 120_000`(2分)。
ユーザーが返信を考えている・他のことをしている間にも2分でAIが話しかけてくるのは
頻度として高すぎる。**修正**: `240_000`(4分)に緩和。

## 調整方針(ユーザーの「飽きさせない」要件への配慮)

- 完全に自発的な声かけを無くす(0にする)のではなく、**間隔を伸ばす**方向で調整した。
  Replika的なプロアクティブ性自体は既存の意図的な設計(companion感の核)であり、
  ゼロにすると「使われていない感」が出て逆効果になりうるため。
- アイドル無発話は元々「一度の無操作期間につき1回だけ」発火する設計だった(発火後に
  タイマーが自動で再起動しない)ため、連続スパムの心配は無く、今回は間隔調整のみで対応。
- greeting抑制の180秒という閾値は「明らかにリロード・再接続」と「実際に少し離れて
  戻ってきた」を分けるための目安。短すぎると本来歓迎すべき再訪問の挨拶まで消えてしまう
  ので、3分程度を妥協値とした。

## 検証

- `npx tsc --noEmit`(frontend・worker)→ いずれも exit 0。
- `python -c "import app.main"`(backend)→ import成功。
- ローカルサーバで `/api/nudge`(reason=greeting)を連続2回叩き、1回目は通常の挨拶文、
  2回目(直後)は `{"text": "", "emotion": "neutral"}` になることを確認。
